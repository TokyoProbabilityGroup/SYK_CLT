# SYK 中心極限定理の編集計画

## 現在の範囲

現在の条件付き CLT は実装済みだが、`AnnealedInput` には現行原稿の `prop:annealed-free-energy` にない追加評価が残る。当面は入力を命題文に合わせ、対数の期待誤差の明示的評価と具体模型への条件付き適用を実装する。命題自体の証明と、そのための外部入力の調査・凸関数列の補題の補完は「その他の残件」とする。原稿との対応と証明状態は [構造文書](ARCHITECTURE.md)、完了済み作業の検証は [作業履歴](../WORK_HISTORY.md#clt-audit-2026-10-04) を参照する。以下の数学的実装予定は未実装である。

## 原稿との整合性と不足部分の実装

現在進める作業の ID・状態・担当・依存関係は [全体計画](../EDITING_PLAN.md#残る作業) に集約する。以下は各作業の仕様と完了条件である。

### 現行命題に合わせたアニール入力の整理

対象は `CLT-INPUT`。分担者の編集範囲は `Basic.lean` と `Main.lean`。文書・Blueprint の対応修正案は成果とともに渡し、統合担当が反映する。範囲外の修正が必要なら対象と理由を報告する。

`Basic.lean` の `AnnealedInput` を [構造文書の入力表](ARCHITECTURE.md#アニール入力の現状と整理後の目標) に従って変更する。削除予定の追加6フィールドを削除し、保持するフィールドを現行の `prop:annealed-free-energy` の命題文に対応させる。

三種類の CLT をまとめた定理と個別定理の結論、規格化、スケーリング、温度範囲を保持して再検証する。削除する評価を別の仮定や互換用宣言として残さない。原稿で維持されている `Z_N≥1`、二次・四次モーメント、高次カオス剰余の評価はこの整理の対象ではない。

整理後の `hFE : AnnealedInput q S` は命題の内容を仮定として受け取る入口とする。構造体のコメントと CLT の README・構造文書・Blueprint を実装へそろえる。完了条件は変更ファイルの個別検査、`lake build CLT`、三種類の CLT をまとめた定理と個別定理の公理依存・残る仮定の確認、原稿との照合である。

### 対数の期待誤差の明示的評価

対象は `CLT-LOG`。分担者の編集範囲は `Lemmas/LogTaylor.lean`、`Lemmas/LogEventBound.lean`、`Lemmas/LogAsymptotics.lean`。統合済みの入力を使い、上流の定義や仮定を変更しない。

`a=q/2-1`、`Y_N=Z_N/E Z_N` とし、原稿の非零の小さい実逆温度で `E[log Y_N]=O(N^(-2a))` を明示的な Lean 定理にする。`N^a` を掛けた期待誤差が零に収束することは実装済みであり、この評価の追加は条件付き CLT 自体の未完成証明を埋める作業ではない。

`LogTaylor.lean`・`LogEventBound.lean`・`LogAsymptotics.lean` の二次モーメント、小確率事象、`Z_N≥1` と `log E Z_N=O(N)` を再利用する。分布収束だけからモーメント評価を推論しない。完了条件は、原稿の評価と同じ指数・中心化・温度条件を照合し、個別検査・関連ビルド・公理依存確認を終えることである。

### 命題を仮定した具体模型への適用

対象は `CLT-APPLY`。`CLT-INPUT` の成果を基に、具体的な公開定理と編集範囲を確定してから割り当てる。

抽象的な `Setting q` から原稿のガウス SYK 模型族への適用条件を明示する。有限サイズの標準表現と規格化は `Normalization.lean` で照合済みだが、それだけで対象模型族への `prop:annealed-free-energy` の適用は得られない。標準模型族、偶数サイズの極限、規格化、表現独立性の要否を照合したうえで、当該模型族について命題の内容に対応する `hFE : AnnealedInput q S` を明示的な仮定とする定理文を確定する。

完了条件は、その仮定の下で三種類の CLT をまとめた定理と個別定理を具体模型族へ適用し、原稿との対応、残る仮定、公理依存を確認することである。`hFE` の構築や命題の証明を、この条件付き適用の完了条件に含めない。

## その他の残件

次の課題は現時点の `CLT-APPLY` や条件付き CLT の完了条件に含めない。再開する場合は全体計画の作業表に戻し、先行成果・数学的仕様・編集範囲・検証条件を確定する。

### 凸関数列の収束補題の補完

対象は保留中の `CLT-CONVEX`。再開時の編集候補は `Lemmas/ConvexDerivatives.lean`。既存の公開定理の型を保持し、不足部分を追加する。個別 Lean 検査と `lake build CLT` も完了条件に含める。

現行の `lem:convex-derivatives` は、全実軸上の微分可能な凸関数列の各点収束と `C¹` 極限から、関数・導関数の局所一様収束を結論する。既存の `convex_convergence_deriv_tendstoUniformlyOn` は関数の局所一様収束を仮定しており、補題全体の形式化ではない。

既存の導関数収束定理を再利用し、各点収束から関数の局所一様収束を導く部分を補い、原稿の全実軸での主張を証明する。原稿の証明省略を理由に外部仮定へ置き換えない。既存の開集合上の定理を維持してよく、不要な一般化は行わない。完了条件は正確な原稿の仮定から両方の局所一様収束を Lean が受理し、主要定理の公理依存を確認することである。

### 外部入力と構築仕様の調査

対象は保留中の `CLT-EXTERNAL`。再開時は固定した原稿、引用元、`Normalization.lean` と既存の入力宣言を読み取り調査する。引用元の版・定理文・規格化・温度範囲・収束・正則性と各フィールドの導出を照合し、残す外部仮定、内部で証明する補題、不足事項、後続の定理文・編集範囲・検証案を報告する。新しい仮定の採用や実装は行わない。

統合担当が調査結果を構造文書と後続仕様に反映する。新たな外部仮定の採否を研究者が判断し、公開定理の仮定と結論、編集ファイルを確定するまで、命題の証明に着手しない。

### `prop:annealed-free-energy` の証明

対象は保留中の `CLT-ANNEALED`。構築定理の正確な型と編集範囲は外部入力の調査後に確定する。現段階の説明だけから API や新規ファイルを作らない。

`Main.lean` の条件付き CLT は、一つの `S : Setting q` と `hFE : AnnealedInput q S` を入力として受け取る。入力整理後は `prop:annealed-free-energy` の内容をこの仮定として扱い、命題自体の Lean 証明は保留する。再開する場合は、入力整理後の命題文を対象とし、He2026 から受け取る結果と原稿内で導く結果を分離する。対象模型、規格化、逆温度の範囲、正則性、収束の種類を確定してから、明示した外部入力から各フィールドを導く。

He2026 の定理自体の全面的な Lean 形式化は現在の計画に含めない。外部結果は名前を付けた明示的な仮定として受け取り、未検証の公理を導入しない。外部入力そのもの、そこからの導出、`AnnealedInput` を用いた条件付き CLT を別々に記録する。必要な導出が得られない場合は、数学的障害と追加判断・再開条件を報告する。完了条件は、確定した外部仮定から入力を構築し、公理依存とは別に残る仮定を確認することである。

`Annealed_FE/refs/SYK-HT-arxiv.tex` は別の Rademacher 模型の原稿であり、そこでの結果をこの入力の構築と同一視しない。`Annealed_FE` は現在の `CLT/Main.lean` の import 先ではない。

## 数学的実装後のリファクタリング

対象は `CLT-REFACTOR`。実装成果の統合後に対象宣言・担当ファイルを確定し、同じ共有ファイルを複数担当へ割り当てない。

現在の実装対象である `CLT-INPUT`、`CLT-LOG`、`CLT-APPLY` を終え、その他の残件を実装するか判断してから、CLT・Model・汎用ガウス基盤・共有 API の利用側を調査する。命題の証明を再開する場合は、その実装後にリファクタリングする。旧作業の未完成部分とは区別した新しい設計課題とする。実装中に循環依存などの解消が必要になった場合だけ、必要最小限の構造変更を先行させる。

実際の利用先と import を基に、重複定義、過剰な依存、不要な変換、補題の所属とファイルの責務を調べる。重点対象は、汎用 Hermite 補題と模型固有の符号対称性、四次モーメント補題から CLT への依存、有限行列解析と規格化トレースの所属である。移設を先に決めず、各変更の対象宣言、移設先、利用側、数学的利点、変更前後の依存、検証対象を確定する。

純粋な整理では宣言名・型・仮定・結論・規格化を保持する。将来の利用だけを見込んだ抽象化、互換用別名、共有層から CLT への逆依存は導入しない。ガウス基盤の `aesop`・`grind` の整理は独立した保守課題として扱う。完了条件は、変更ファイルと利用側の検査、関連ビルド、共有層の変更時の既定ビルド、主要定理の公理依存と定理文の再照合である。

## 新たに一様な複素領域を必要とする場合

新しい利用側が一様な複素非零領域を必要とする場合は、[共有模型の現行結果と仮定](../Model/ARCHITECTURE.md#複素逆温度を扱う定理の仮定) を確認し、領域、行列の範囲、一様性を別課題として指定する。
