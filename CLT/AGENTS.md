## 保護する数学的内容

CLT の有限模型の証明は一般の `Params` と `MajoranaSystem`、漸近証明は `S : Setting q` を入力とする。`q` の偶数性と `4 ≤ q` は `S` のフィールドを用い、重複した入力を要求しない。Proposition 4.2 は `hFE : AnnealedInput q S` として仮定し、その構築を CLT の完了条件にしない。`Setting` に新しい仮定を追加しない。

`FiniteModel.lean` は抽象的な有限模型の定義・評価・モーメントを置く。`Normalization.lean` は標準表現との有限サイズの規格化照合だけを置き、`Main.lean` とその証明依存から import しない。現行の抽象的な条件付き CLT の証明に、標準模型専用の `Setting`・`AnnealedInput`・CLT や標準表現の再構成を持ち込まない。具体模型での `AnnealedInput` の構築と適用は別課題として扱う。未検証の公理は追加しない。

明示的な承認なしに、`M_N`、`sigma_N`、`H_N`、`Z_N`、`Y_N` の定義、スケーリング `N^(q/2-1)`、極限分散、逆温度の範囲、相対ゆらぎ・標準化したゆらぎ・対数のゆらぎに対する中心極限定理（CLT）の区別、および各結果の収束の種類を変更しない。

各ゆらぎの定義、極限分散、中心化の差は `ARCHITECTURE.md` の「現行原稿の主張」と「対数 CLT の新しい経路」を参照する。

現行 CLT の主定理の実装・原稿は実数 `β` と高温条件 `|β| < βq` および `β ≠ 0` を用いる。以前の非負逆温度への移行案を理由にこの範囲を変更しない。共有模型の物理的 Gibbs・集中 API の `β : ℝ≥0` は維持し、CLT の実数逆温度の結果は必要な適用を明示して導く。解析の `z : ℂ` と確率論の `β : ℝ` は区別する。

CLT の規格化分配関数は一般の非空有限次元 `MajoranaSystem` の実際の次元で割る。標準表現への特殊化による原稿との対応と、一般表現への外部極限定理の適用可能性を別に照合する。有限模型の結果に、最終 CLT や `AnnealedInput` を使わない。

複素対数微分に現れる `Z z ≠ 0` は、Z01 で証明した固定自己共役有限行列の局所円板など、適用可能な非零性の定理がない場合は仮定として明示する。Z01 の半径を `N` や乱数標本に一様なものとして扱わない。

## 証明と未完了事項の確認

証明を変更・説明する際は `ARCHITECTURE.md` の分解と依存関係を確認する。高次カオスの剰余項には、`refs/sections/higher-chaoses.tex` のラデマッハ変数による符号化と指数モーメントによる直接評価を用いる。対数 CLT は有効な本文の `Z_N≥1` と小確率事象による証明を基準にする。

作業前に `EDITING_PLAN.md` の未完了事項を確認する。定理文に関わる問題の調査と修正案の作成は、指定された範囲で進めてよい。ただし、その修正を単なる誤植修正として処理せず、定理文や採用する前提を変更する前に人間の研究者の承認を得る。判断事項は該当項目にまとめ、別の承認済み作業まで一律に停止させる前提にしない。

## 共同実装の着手条件

新しい CLT 作業では、[全体計画](../EDITING_PLAN.md) と [詳細計画](EDITING_PLAN.md) から未完了事項を確認し、完了済みの番号を新たな実装課題として扱わない。正確な定理文・入力、編集担当、検証対象を確定する。指定課題に不足する前提があれば、その調査と障害の報告まで進め、未承認の仮定・定理文を仮置きしてコードを書かない。原稿本文の編集は明示的に担当を依頼された場合に限る。

部分積分は共有ガウス基盤の既存宣言を利用し、原稿の `η ≤ α` の範囲を超える偏導関数の成長仮定を暗黙に追加しない。外部コードを流用するときは、流用元の証明と移植後の Lean 検証を区別する。

複数担当で作業するときは同じ開始時点の独立した作業領域を使い、共有作業ツリー上の同時編集を避ける。同じファイルへの変更は担当補題と入力 API を先に分け、一人の統合担当が直列に取り込む。全体の進捗・Blueprint の更新もその担当に集約する。Lean 実装担当は原稿を編集せず、不一致は根拠付きで報告する。Blueprint は統合・検証済みの宣言に合わせて更新し、既存の未形式化ノードは計画として区別して残す。Verso の機械的検査は休止したままとする。明示的に別の作業を依頼された場合は、その範囲と承認条件を先に確認する。

## Lean の依存関係

`SYK.CLT` は共有の `SYK.Probability.GaussianConcentration`・`SYK.Model` と、必要な場合の `SYK.SuperConcentration` を利用し、共有部分から CLT への `import` は作らない。`Basic.lean` が `prop:annealed-free-energy` に合わせた `AnnealedInput q S` を宣言し、現行 `Main.lean` は `SYK.Annealed_FE.main_result` を import しない。

`Lemmas/` の探索は [README の案内](README.md#finding-a-lemma) から始める。宣言名と利用箇所を `rg` で探し、対象の定理文と周辺の必要な証明だけを読む。型の確認には `#check` や `#print` を使い、大きな `GaussianIBP.lean` を通常の補題利用のために全文走査しない。

補題ファイルは一つの数学的役割または証明の層に対応させ、再編では依存が閉じた部分ごとに移す。`Tool`・`Utils`・`Misc` のような雑多な補題の置き場、宣言一覧だけの Lean ファイル、既存定理を包むだけの API は作らない。集約用モジュールが必要なら `import` だけにする。純粋なファイル再編では公開宣言の名前・名前空間・型・仮定・属性・規格化を保ち、旧パスの互換用モジュールを作らず利用箇所を更新する。

新しいモジュールと直接の利用先を個別に検査してから `lake build CLT` を実行する。

Lean のコメントとドキュメント文字列では、`Theorem 1.2` や `Lemma 3.3` のような原稿編集で変わる番号ではなく、TeX の `\label{...}` をバッククォートで囲んで参照する。対応するラベルがない結果は勝手に命名せず、TeX にラベルを追加するか、現在ラベルがないことを明記する。
