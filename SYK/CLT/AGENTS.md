## 適用範囲と参照先

`SYK/CLT/` 以下に適用する。ワークスペースと [リポジトリの規則](../../AGENTS.md) も適用する。

作業前に、[全体計画](../../EDITING_PLAN.md) の残件、[詳細計画](EDITING_PLAN.md) の残件と完了条件、[構造文書](ARCHITECTURE.md) の数学的規約と依存を確認する。原稿の正確な主張は `../../Paper/CLT_SYK.tex` とそこから読み込む本文、Lean の型と証明項は Lean ソースで確認し、不一致を黙って統合しない。完了済みの検証根拠は、必要なときに [作業履歴](../../WORK_HISTORY.md) を読む。

## 保護する数学的内容

- 有限模型には一般の `Params` と `MajoranaSystem`、漸近結果には `S : Setting q` を用いる。`q` の偶数性と `4 ≤ q` を重複して要求せず、`Setting` に新しい仮定を追加しない。
- [模型・型・規格化](ARCHITECTURE.md#模型型規格化) と [原稿の主張](ARCHITECTURE.md#現行原稿の主張) を照合し、定義、スケーリング、極限分散、実逆温度の範囲、中心化、収束の種類を承認範囲外で変更しない。相対・標準化・対数 CLT を区別し、以前の非負逆温度への移行案を適用しない。
- 非空有限次元表現の実際の次元による規格化を保つ。標準表現との有限サイズの照合と、外部極限定理の適用可能性を区別する。
- 抽象的な条件付き CLT と `AnnealedInput` の構築・具体模型への適用は別課題とする。有限模型の証明に最終 CLT や `AnnealedInput` を使わない。
- 原稿の証明経路は構造文書を参照し、旧集中評価を対数 CLT の必須入力に追加しない。局所非零円板を `N`・乱数標本に一様な領域として扱わない。
- 部分積分は共有ガウス基盤を利用し、原稿の `η ≤ α` を超える偏導関数の成長仮定を追加しない。外部コードの証明と移植後の Lean 検証を区別する。

## 依存と検証

共有模型・汎用ガウス基盤から CLT への `import` は作らない。`FiniteModel.lean` に一般の有限模型、`Normalization.lean` に標準表現との有限サイズの照合を置き、後者を抽象的な `Main.lean` とその証明依存へ import しない。入力構築・具体模型への適用を抽象 CLT の証明へ混在させない。

補題の探索は [README の案内](README.md#finding-a-lemma) から始め、宣言名・利用箇所・型と必要な証明だけを確認する。補題ファイルは数学的役割または証明の層に対応させ、雑多な `Tool`・`Utils`・`Misc` や宣言一覧だけのファイルは作らない。必要な集約モジュールは `import` だけにする。純粋な再編では、公開宣言の名前・名前空間・型・仮定・属性・規格化を保つ。

Lean ファイルを変更したら、変更ファイルと直接の利用先を個別に検査してから `lake build SYK` を実行する。主要定理の公理依存、残る仮定、原稿との対応を確認する。
