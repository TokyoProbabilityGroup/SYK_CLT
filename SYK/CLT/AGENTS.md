## 適用範囲と参照先

このファイルはリポジトリ内の `SYK/CLT/` 以下に適用する。ワークスペースのルートと [SYK の規則](../../AGENTS.md) も適用する。

作業前に、[全体計画](../../EDITING_PLAN.md) の担当・作業間の依存関係、[詳細計画](EDITING_PLAN.md) の仕様・完了条件、[構造文書](ARCHITECTURE.md) の数学的規約・依存を確認する。正確な原稿の参照元は `../../Paper/CLT_SYK.tex` とそこから読み込む本文である。Lean の型と証明項は Lean ソースを確認し、不一致を黙って統合しない。完了済みの検証根拠は必要時に [作業履歴](../../WORK_HISTORY.md) を読む。

## 保護する数学的内容

- 有限模型には一般の `Params` と `MajoranaSystem`、漸近結果には `S : Setting q` を用いる。`q` の偶数性と `4 ≤ q` を重複して要求せず、`Setting` に新しい仮定を追加しない。
- [模型・型・規格化](ARCHITECTURE.md#模型型規格化) と [原稿の主張](ARCHITECTURE.md#現行原稿の主張) を照合し、定義、スケーリング、極限分散、実逆温度の範囲、中心化、収束の種類を承認範囲外で変更しない。相対・標準化・対数 CLT を区別し、以前の非負逆温度への移行案を適用しない。
- 非空有限次元表現の実際の次元による規格化を保つ。標準表現との有限サイズの照合と、外部極限定理の適用可能性を区別する。
- 抽象的な条件付き CLT と `AnnealedInput` の構築・具体模型への適用は別課題とする。有限模型の証明に最終 CLT や `AnnealedInput` を使わない。
- 原稿の証明経路は構造文書を参照し、旧集中評価を対数 CLT の必須入力に追加しない。局所非零円板を `N`・乱数標本に一様な領域として扱わない。
- 部分積分は共有ガウス基盤を利用し、原稿の `η ≤ α` を超える偏導関数の成長仮定を追加しない。外部コードの証明と移植後の Lean 検証を区別する。

## 共同実装

対象の特定・編集範囲・承認条件は [上位の規則](../../AGENTS.md#短い依頼と分担範囲) に従う。原稿の改訂中も課題ごとに固定した版で進め、改訂の影響は [同期手順](../../EDITING_PLAN.md#原稿改訂と実装の同期) で確認する。記法変更だけを理由に Lean 宣言を改名したり互換用別名を追加したりしない。

## Lean の依存関係と編集

共有模型・汎用ガウス基盤から CLT への `import` は作らない。`FiniteModel.lean` に一般の有限模型、`Normalization.lean` に標準表現との有限サイズの照合を置き、後者を抽象的な `Main.lean` とその証明依存へ import しない。入力構築・具体模型への適用を抽象 CLT の証明へ混在させない。

補題の探索は [README の案内](README.md#finding-a-lemma) から始め、宣言名・利用箇所・型と必要な証明だけを確認する。大きな `GaussianIBP.lean` を通常の補題利用のために全文走査しない。

補題ファイルは数学的役割または証明の層に対応させる。雑多な `Tool`・`Utils`・`Misc`、宣言一覧だけのファイル、既存定理を包むだけの API は作らない。必要な集約モジュールは `import` だけにする。純粋な再編では公開宣言の名前・名前空間・型・仮定・属性・規格化を保ち、互換用の旧パスを作らず利用箇所を更新する。

## 検証と文書

Lean ファイルを変更した場合は、変更ファイルと直接の利用先を個別に検査してから `lake build SYK` を実行する。主要定理の公理依存、残る仮定、原稿との対応を確認する。調査・文書編集のみの場合は上位規則に従う。

独立した証明状態表・問題台帳・作業日誌は追加せず、数学的な対応は構造文書、細目・完了条件は詳細計画、作業状態・担当は全体計画、完了済みの検証は作業履歴に集約する。
